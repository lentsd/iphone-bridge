# Данные и публикация

## Что хранится локально

По умолчанию iPhone Bridge использует `~/Library/Application Support/iPhone Bridge/`.

| Данные | Где и зачем |
| --- | --- |
| Apple ID владельца архива и последний подтверждённый аккаунт | `library.json`, для связи IPA с аккаунтом и проверки перед скачиванием. |
| Идентификатор, имя и версия iOS исходного телефона | `library.json`, для списка источника и блокировки установки на него. |
| Список приложений и App Store ID | `library.json`, для выбора и повторных операций. |
| Пакеты IPA | Подпапка `Архив`. Пакеты могут содержать метаданные владельца или лицензии. |
| Скрипт входа | В той же папке, содержит путь к ipatool и команды запуска; пароль в него не записывается. |
| Состояние авторизации | Отдельное хранилище ipatool и используемых им библиотек; не входит в `library.json`. |
| Подготовленные компоненты Apple | Кэш ipatool, используется повторно после проверки. |

При разработке `IPHONE_BRIDGE_DATA_DIR` меняет папку библиотеки. Она должна оставаться вне отслеживаемых файлов Git.

Приложение не сохраняет пароль и 2FA в своём журнале и не передаёт их в аргументах процесса. Строки ошибок, пути к файлам, адрес аккаунта в интерфейсе и имя телефона всё равно могут раскрывать личные сведения на скриншотах и в диагностике. Подробные диагностические режимы сторонних инструментов требуют отдельной проверки перед публикацией.

## Сетевые обращения

У iPhone Bridge нет собственного сервера, аналитики или телеметрии. Авторизация, получение конфигурации, служебный обмен и скачивание выполняются через сервисы Apple. Первичная подготовка компонентов и сборка зависимостей также используют внешние ресурсы, заданные в исходниках ipatool и скриптах сборки. Это не офлайн-приложение.

Системному транспорту служебных URL не передаются Cookie и Authorization. Это ограничение касается выбранных служебных запросов; настоящий вход в Apple ID по своей природе отправляет данные авторизации Apple.

## Что исключено из репозитория

`.gitignore` исключает готовое приложение, бинарные сборки, IPA, кэши, журналы, локальные библиотеки, типовые файлы учётных данных и настройки редакторов/агентов. Примеры в тестах синтетические и используют зарезервированный домен `example.invalid`.

Исходный архив ipatool — сторонний публичный исходный код, а не архив устройства или аккаунта. Его лицензия и сведения о происхождении сохранены.

Перед публикацией изменений проверяй **содержимое Git index**, а не только `.gitignore`:

```sh
git status --short
git diff --cached --stat
git diff --cached
git ls-files
```

Игнорирование не убирает файл, уже попавший в коммиты. Если секрет был отправлен в репозиторий, сначала отзови его, затем отдельно очищай историю. Не прикладывай реальные IPA, `library.json`, конфигурацию авторизации, пароли, коды 2FA, идентификаторы телефонов и полные журналы к issues.

## Выход и удаление данных

Команда `ipatool auth revoke` выполняет выход средствами модуля. Она не удаляет библиотеку, IPA и сохранённые метаданные владельцев. Для удаления локальной библиотеки закрой программу, при необходимости сделай защищённую резервную копию и удали соответствующую папку вручную. Удаление кэша ipatool потребует повторной подготовки компонентов.
