# Разработка и проверка

## Сборка с чистого клона

Требования: Apple silicon, macOS 26+, Command Line Tools for Xcode, Go 1.27+, Python 3.9+, curl и доступ в интернет для зависимостей Go.

```sh
bash Scripts/build-ipatool.sh
bash Scripts/build.sh
open "dist/iPhone Bridge.app"
```

`build-ipatool.sh` проверяет закреплённый исходный архив, применяет локальный патч, собирает модуль с `-trimpath` и обновляет `Vendor/ipatool/PROVENANCE.json`. Бинарный файл не хранится в Git. Сборка не включает IPA, состояние авторизации, кэш компонентов Apple или библиотеку приложения.

`build.sh` компилирует helper на Objective-C и приложение на Swift, копирует ipatool, его лицензию, сведения о происхождении и инструкцию. Затем выполняет локальную ad-hoc подпись. Готовый пакет появляется в `dist/iPhone Bridge.app`.

Не заменяй пакет приложения во время передачи файлов. Для сборки в отдельную папку:

```sh
IPHONE_BRIDGE_APP_PATH="$PWD/.build/iPhone Bridge.app" bash Scripts/build.sh
```

## Тесты приложения

```sh
bash Scripts/test.sh
```

Проверяются чтение синтетических IPA, повреждённые и неподходящие пакеты, разбор App Store ID, хеши, ограничения установки, сохранение библиотеки, разные владельцы одного файла, смена аккаунта и новый перенос. Тесты не обращаются к Apple ID или подключённым телефонам.

Отчёты JSON сохраняются в `.build/` или в папке из `BB_THREAD_STORAGE`, если эта переменная задана. Папка отчётов должна оставаться вне публикации.

## Изменение патча ipatool

`Scripts/update-ipatool-patch.py` сравнивает явный список изменяемых файлов с закреплённым архивом. Для работы подготовь редактируемое дерево:

```sh
mkdir -p .build/ipatool-upstream
tar -xzf Vendor/ipatool/source-001d889.tar.gz \
  -C .build/ipatool-upstream --strip-components=1
patch -p1 -d .build/ipatool-upstream < Vendor/ipatool/bridge-preparation.patch
# Внести изменения, выполнить gofmt для изменённых Go-файлов
python3 Scripts/update-ipatool-patch.py
bash Scripts/build-ipatool.sh
```

Подготовку дерева выполняй один раз в пустой папке. Для нового файла добавь его в явный список `PATHS` генератора патча.

Для тестов upstream используются `go generate ./...` и `go test ./...` в редактируемом дереве. Они могут загружать инструменты и зависимости, а полный upstream-набор имеет собственные требования. Итоговый модуль собирай через `build-ipatool.sh`: он использует чистую распаковку, чтобы сгенерированные моки не попали в production-сборку.

## Проверка сети без аккаунта

```sh
Vendor/ipatool/bin/ipatool bridge-prepare
Vendor/ipatool/bin/ipatool bridge-check-sap
```

Первая команда проверяет публичную конфигурацию Apple, подготавливает компоненты и проверяет сертификат. Вторая создаёт служебную SAP-сессию и получает тестовую подпись. Обе обращаются к сети и кэшу, но не выполняют вход в Apple ID. Результат не гарантирует успешную авторизацию или доступ к конкретному приложению.

## Демонстрационный скриншот

```sh
"dist/iPhone Bridge.app/Contents/MacOS/iPhoneBridge" \
  --render-preview /tmp/iphone-bridge-demo.png --apps
```

Это явный режим с синтетическими телефонами и аккаунтом `example@example.invalid`. Он не запускает обычные операции, не читает личную библиотеку и не обращается к устройствам. Флаг `--archive` выбирает демонстрацию архива; без обоих флагов показывается подключение.

## Проверка на устройствах

Реальная авторизация и скачивание проверены вручную. Для каждой новой комбинации macOS/iOS и каждого пакета отдельно проверяй сопряжение, чтение списка, загрузку, установку и запуск. Автоматические тесты не доказывают совместимость непубличного API MobileDevice или доступность приложения у Apple.
