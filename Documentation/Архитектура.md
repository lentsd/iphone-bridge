# Архитектура

## Компоненты

`Sources/App.swift` запускает SwiftUI-приложение, задаёт меню и обрабатывает завершение. Во время активной операции штатное закрытие блокируется. Явный режим `--render-preview` использует только синтетические данные и не читает библиотеку или аккаунт.

`Sources/Views.swift` содержит четыре раздела: подключение, список приложений, архив IPA и помощь. Действия выполняются через `BridgeModel`.

`Sources/Models.swift` описывает устройства, приложения, записи архива и сохранённое состояние. Здесь же находятся нормализация идентичности аккаунта, разбор App Store ID и проверки установки.

`Sources/Services.swift` управляет состоянием интерфейса, дочерними процессами, SHA-256, библиотекой и последовательностью операций. Вход открывает сгенерированный скрипт в Terminal; пароль не передаётся в командной строке.

`Sources/DeviceBridge.m` — отдельный JSON helper. Он динамически подключает системный MobileDevice.framework, находит USB-устройства, выполняет сопряжение, читает приложения и устанавливает IPA. Для чтения метаданных ZIP используется системный libarchive без распаковки на диск.

`Vendor/ipatool` — закреплённый исходный архив ipatool и локальный патч. Собранный модуль входит в пакет приложения и отвечает за авторизацию, историю покупок и скачивание.

## Основной поток

```mermaid
flowchart LR
    A[Исходный iPhone] -->|USB: список приложений| B[iPhone Bridge]
    B -->|Terminal: вход и 2FA| C[ipatool]
    C -->|HTTPS| D[Сервисы Apple]
    D -->|Доступный аккаунту IPA| E[Локальный архив]
    B -->|Проверка SHA-256 и метаданных| E
    E -->|MobileDevice по USB| F[iPhone-получатель]
```

Установленные файлы со старого телефона не извлекаются. Телефон нужен для списка приложений и идентификации источника. Файлы скачиваются отдельно при наличии доступа у Apple ID.

## Проверки установки

- Получатель выбран явно и отличается от текущего исходного телефона и источника конкретной записи архива.
- Путь соответствует имени файла в библиотеке; переходы по каталогам в имени запрещены.
- SHA-256 совпадает с сохранённым значением.
- В IPA ровно один основной `Payload/*.app/Info.plist`; метаданные имеют ограниченный размер, количество записей ограничено.
- Bundle ID совпадает с выбранным приложением, семейство включает iPhone, минимальная версия iOS подходит получателю.
- Уже установленный полный пакет пропускается.
- Передача и установка выполняются последовательно; затем приложение ищется в списке установленного ПО.

Эти проверки не заменяют проверку криптографической подписи и лицензии со стороны iOS.

## Библиотека и аккаунты

`library.json` хранит исходное устройство, список приложений, переопределения App Store ID, архив и последний подтверждённый аккаунт. Запись архива содержит SHA-256, размер, имя файла, дату, сведения о приложении, источник и необязательный Apple ID владельца. Старые записи без владельца остаются читаемыми.

Физический файл может использоваться несколькими записями с разными владельцами или источниками. Новый перенос сохраняет архив и авторизацию; смена аккаунта сбрасывает временные выборы и историю. Перед скачиванием фактический аккаунт ipatool сверяется с подтверждённым в интерфейсе.

## Служебное соединение Apple

`bridge-prepare` проверяет тот же URL bag и аппаратную идентичность Mac, что использует вход, затем проверяет компоненты и сертификат. Общий контекст подготовки ограничен тремя минутами.

Для ограниченного набора служебных URL используется `/usr/bin/curl` с проверкой TLS, ограничениями времени и объёма. Параметры URL bag разрешают только ожидаемые `guid` и `ix`. Заголовки аккаунта исключены из этого пути. Авторизация Apple ID остаётся отдельной операцией ipatool.
